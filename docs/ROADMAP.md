# Current priority: .NET Framework 4.8.1 prerequisite 5100

**New original Microsoft .NET 4.8 MSI control, not another bootstrapper argument:** Authenticated offline NDP48 has repeatedly exited **5100** on Apple Silicon Wine even when .NET 4.0 executes genuine x64 managed code. Microsoft documents 5100 as system requirements not met. References on real Windows 7 and Wine also show the original offline installer supports extraction to `netfx_Full_x64.msi` and `netfx_Patch_x64.msp`, then installation with Windows Installer rather than its top-level setup EXE (see [Windows 7 native MSI isolation](https://lolcads.github.io/posts/2022/03/win7_dotnet_install/) and [Raven native MSI example](https://www.starryhope.com/linux/raven-windows-apps-linux/)). To test whether **the setup wrapper**, rather than MSI servicing/runtime functionality, is the main blocker, a separate main-only experiment takes the already Authenticode-verified and SHA256-matched original Microsoft NDP48 media, extracts unmodified packages to the disposable prefix with its documented `/x` mode, requires exact x64 MSI/MSP files with real OLE MSI headers and safe paths, then tries genuine MSI installation and its original patch with bounded runtime and private outputs. Neither MSI success nor package presence establishes working Framework. Native 4.8 success requires **both** MSI and MSP exits succeeded, Wine restart, *changed* authentic-shaped x64 CLR64, correct real Release registry value, native CLR loader and working native-only x64 managed execution. This is unsupported as an official Windows setup method and may fail or be inapplicable; its purpose is to separate the 5100 bootstrapper compatibility defect from the Windows Installer component and possibly advance real native installation. No fake registry/TrustedInstaller service, proprietary upload or manufactured Microsoft binary is permitted. The original 4.8.1/SOLIDWORKS gates remain closed until authentic runtime checks pass.
